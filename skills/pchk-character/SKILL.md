# Лист персонажа ПЧК

Результат: `<имя>.pchk.pptx`, PDF для печати, исходный `<имя>.draft.json` и портрет, если он есть.
Согласованное оформление: оригинальные фон, щиты и подписи характеристик; редактируемые цифры
и тексты; портрет слева и предыстория справа на второй странице. Шрифты Cambria и Impact.
Размер страницы 210 × 148 мм. Шаблон включён в `assets/character-sheet.pptx`: не ищи его
в «Загрузках» или временных файлах прошлых сессий, не собирай весь лист одной картинкой.

## Содержание персонажа

Извлеки максимум из запроса, анкеты или старого листа. Сохраняй заданные пользователем значения.
Если просят придумать героя, выбирай недостающее самостоятельно и кратко сообщи принятые решения.
Уточняй только противоречия или сведения, без которых изменится замысел пользователя.

ПЧК здесь означает оформление и краткую подачу, а не установленный официальный свод правил.
Для нового героя по умолчанию используй D&D 5e 2014 как основу; если задана другая редакция,
система или авторские правила, следуй им. Авторские умения обозначай как адаптацию, не выдавай
их за канон шоу или RAW. Проверяй механику по выбранным правилам; не смешивай редакции молча.

В шести щитах показываются **модификаторы**, например +3, а не значения характеристик вроде 16.
Владение оружием и навыки содержат итоговые бонусы. КД учитывает доспехи и щит ровно один раз;
вариант `14/16` требует пояснения условий. У ограниченных умений укажи число применений и
восстановление. У атак сохрани бонус, урон, дальность и существенные условия; у эффектов —
действие, спасбросок, длительность и ограничения. Сокращение текста не должно менять механику.
Не переноси контакты игрока из анкеты в лист.

Не пытайся вместить полный справочник заклинаний в две страницы. При переполнении убери
повторения и сократи формулировки. Если важное всё ещё не помещается, предложи дополнительный
лист вместо незаметной потери правил.

## Портрет

Используй присланное изображение. Если при создании нового героя картинки нет, создай портрет
доступным инструментом генерации изображений, если пользователь не просит без иллюстрации.
Применяй соответствующий навык генерации изображений, если он доступен. Нужен вертикальный кадр
примерно 5:7: лицо и важные детали не у краёв. Если генерация недоступна, собери текстовую часть,
оставь `portrait: null` и сообщи об отсутствии портрета. Не подставляй другого героя.
Скрипт встраивает картинку и обрезает её без искажения пропорций; фокус задаётся в черновике.

## Сборка

Все пути ниже относительны папке скилла. Перед первым черновиком прочитай
[формат данных](references/draft-format.md) и пример `assets/example.draft.json`.

1. Найди Python 3.10+ и установи зависимости из `requirements.txt` в папке скилла:
   `python -m pip install -r <skill>/requirements.txt`. Команда Python может называться `python3`.
   Шаблон, шрифты с кириллицей и переносимый PDF-экспорт уже в архиве; PowerPoint не обязателен.
   `--renderer auto` использует PowerPoint в Windows, если доступен, иначе переносимый экспорт.
   `--renderer portable` всегда работает через Python (ReportLab и PDFium), в том числе в Linux.
   У переносимого PDF шрифты PT Serif и Anton вместо Cambria и Impact; вид может немного отличаться.
2. Сохрани JSON UTF-8 в выбранной пользователем папке, иначе в рабочем каталоге. Текстовые файлы
   в Windows записывай с CRLF. Портрет сохрани рядом, путь в JSON — относительно черновика.
3. Проверь и собери (вместо `<skill>` подставь абсолютный путь):

   ```text
   python <skill>/scripts/pchk.py validate <имя>.draft.json
   python <skill>/scripts/pchk.py build <имя>.draft.json --pdf --preview
   ```

   PPTX появляется рядом с черновиком; `--output-dir` меняет папку. Существующие результаты
   не перезаписываются без `--force`. Пересборку собственного результата можно делать с `--force`,
   если она соответствует запросу пользователя. Исходный шаблон не изменяется.
4. Скрипт проверяет данные и приблизительную вместимость; выбранный рендерер проверяет размещение
   текста и экспортирует PDF и PNG. При переполнении исправь черновик и пересобери.
   `validate` проверяет структуру, а не баланс или переносы. Сборка без `--pdf` и `--preview`
   создаёт только PPTX без проверки итогового отображения.
5. Открой оба PNG и проверь текст, щиты и портрет. Отчёт `*.render-report.json` служебный;
   успешное выполнение скрипта не заменяет визуальную проверку. Переносимый рендерер поддерживает
   именно этот шаблон, а не произвольные презентации. Не заявляй о готовом PDF, которого нет.

## Агенты и браузерные чаты

Этот скилл — папка с инструкциями и локальными скриптами, не плагин конкретного поставщика.
Пути определяй от расположения `SKILL.md`, не от домашней папки автора. Не требуй инструментов
Codex, Claude, аккаунта LSS или подключения к стороннему API для сборки.
Архив распаковывай доступными файловыми средствами; в чате с Python можно применить `zipfile`.
Результаты сохраняй там, откуда текущая среда умеет выдавать файлы пользователю.
Если чат не может исполнять код или выдавать файлы, сообщи это и подготовь черновик с командой
локальной сборки; не имитируй создание PPTX/PDF и не обещай, что расширение `.skill` добавит инструменты.

Изменения вноси в черновик и пересобирай: это позволяет воспроизводить лист при повышении уровня.
Скрипт заполняет шаблон по именам элементов, сохраняет стили и макеты. При запросе нового пустого
шаблона копируй `assets/character-sheet.pptx` вместо генерации героя.

## Выдача

Дай ссылки на PPTX и PDF, отдельно на черновик при необходимости дальнейших изменений.
Кратко укажи концепцию, принятые механические допущения и существенные ограничения.
Не публикуй созданных персонажей во внешние сервисы без запроса. Лицензия программного кода
не распространяется на стороннее оформление и шрифты; сведения об источниках — в `NOTICE`
(в исходном репозитории — `../NOTICE`) и
файлах лицензий шрифтов. Не представляй скилл как официальный продукт авторов шоу.
